### What is tested

* **Examples** - one MedicationRequest per dose unit (`input/fsh/examples.fsh`). They declare no profile, so each is
  valid base FHIR and appears in this guide. A unit that is not UCUM at all (`tablet`) would make an invalid example,
  so it is kept apart, in `tests/invalid/`.
* **Profiles** - MedicationRequest profiles that differ only in the binding on the dose quantity
  (`input/fsh/profiles.fsh`).
* **Value sets** - one per way of restricting UCUM (`input/fsh/valuesets.fsh`).

### Rerunning the tests

The results on [How UCUM works](ucum.html) are generated by `tests/run-tests.mjs`. It needs Java and Node.js, and the
FHIR validator ([validator_cli.jar](https://github.com/hapifhir/org.hl7.fhir.core/releases/latest/download/validator_cli.jar))
in `input-cache/` or at `VALIDATOR_JAR`.

```
sushi build .
node tests/run-tests.mjs
```

It runs the validator once per profile over all the examples, calls `$validate-code` on a terminology server for each
unit and value set, and writes the tables to `input/includes/results-*.md` (and the raw results to `tests/output/`).
Then build the guide as usual. To use another terminology server, set `TX`, e.g. `TX=https://tx.fhir.org/r4`.

### The Bruno collection

The `bruno/` folder is a [Bruno](https://www.usebruno.com/) collection with the same terminology checks as single
requests, each asserting the expected result. It is useful to try one case by hand, or to check a terminology server.

* Open the `bruno` folder in Bruno, pick an environment, and run the collection or one request.
* Or from the command line: `cd bruno` then `npx @usebruno/cli run -r --env sslip`.

Environments: `sslip` (FHIRsmith at `https://178.104.103.200.sslip.io/tx/r4`), `tx-fhir-org`, `tx-hl7europe`, `local`.
The requests are generated from this guide's value sets and examples by `bruno/generate.mjs` - rerun it after changing them.
